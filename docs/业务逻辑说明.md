# 发票报销助手 — 完整业务逻辑说明

## 1. 文件识别入口

系统通过 **Tauri 命令层** (`lib.rs`) 暴露 15+ 个命令给 Vue 前端，主要的入口有两个：

| 方式 | 命令 | 说明 |
|------|------|------|
| **全局导入** | `batch_global_import(dir_path)` | 用户选择一个文件夹，系统**递归遍历**所有文件 |
| **单个/批量** | `batch_recognize(paths)` / `recognize_invoice(path, type)` | 用户选择具体文件 |

**文件扩展名识别规则** (`lib.rs:284-317`)：
- `.pdf` → 批量收集后统一走 `invoice_pipeline::parse_all_from_files`（先尝试发票解析，失败则尝试行程单解析）
- `.jpg/.jpeg/.png` → 逐个调用 `parse_invoice_from_image`（OCR 识别）
- `.xlsx/.xls` → 走 `wechat_parser`（微信账单）
- `.csv` → 走 `alipay_parser`（支付宝账单）
- 其余扩展名 → 忽略

---

## 2. 发票文本提取（PDF 优先文字，图片走 OCR）

`text_extractor.rs` / `invoice_pipeline.rs`

对每个 PDF 文件：

1. **PDF 文档类型分类** (`classify_pdf_document_type`)：识别文本中是否含 "行程单" / "结账单" / "发票" 关键字
2. **文字提取优先**：先用 `parangi`（Apache PDFBox 移植，支持 CJK），失败回退 `pdf-extract`
3. **文字足够**（>20字符）→ 直接使用提取文字；**文字不足** → 回退到 OCR
4. 图片文件 → 直接走 **PaddleOCR** (`ocr-engine` / `ocr-rs` crate)，识别结果按页返回带坐标的文本块

**文档类型过滤**：非发票/行程单类型会被 `check_and_parse` 拒绝（返回错误 "非发票类型"）

---

## 3. 发票解析与分类

### 3.1 核心解析路径

`invoice_parser.rs` 提供两条路径：

**路径 A：传统文本解析** (`parse_invoice_text`)
- 将 OCR 文本按区域切分为 `header/buyer/seller/items/total/remarks` 六个区域
- 使用正则提取：金额 (`价税合计[：:￥¥]*...`)、销售方名称、项目名称、日期、发票号码
- 区域分类 → `classify_from_regions`

**路径 B：结构化 OCR 解析** (`parse_structured_invoice`)
- 先用 **JSON 模板**匹配（`template_manager.rs`，`config/invoice_templates/` 下有 5 个模板），匹配成功则用模板提取
- 无模板匹配 → 用 `FieldExtractor` 策略链提取各字段
- 全文分类 → `classify_from_full_text`

### 3.2 发票类型检测 (`invoice_type_detector.rs`)

检测顺序（**优先级从高到低**）：
1. **RideHailingItinerary**（行程报销单 / 滴滴/高德行程单）
2. **TransitCardStatement**（天府通电子行程单）
3. **FlightInvoice**（机票/航班/航空）
4. **VatElectronicInvoice**（增值税电子发票）
5. **HotelStatement**（酒店结账单）
6. **TrainInvoice**（火车票/高铁/G/D车次号+站/铁路）
7. **RideHailingInvoice**（滴滴/高德/T3/曹操不含"行程单"）
8. **Other**

### 3.3 发票类别分类 (`InvoiceCategory`)

7 个类别：`Train`, `Flight`, `TicketChange`, `CityTransport`, `Hotel`, `Meal`, `Other`

**分类优先级**（`classify_from_regions` / `classify_from_full_text`）：
1. **税收编码匹配**（最可靠）：`*住宿服务*`→Hotel, `*运输服务*`→需再判断是否含火车/高铁（Train）或航空（Flight），否则 CityTransport, `*航空运输服务*`→Flight, `*餐饮服务*`→Meal
2. **商品名称关键词**：住宿/酒店/宾馆→Hotel, 机票/航空→Flight, 火车/高铁→Train, 餐饮/饭店→Meal
3. **卖家名称关键词**：滴滴/高德/网约车/T3/曹操→CityTransport, 酒店/宾馆/住宿→Hotel, 航空/机票→Flight, 铁路/高铁→Train
4. **发票类型推断**：`InvoiceType::FlightInvoice`→Flight, `TrainInvoice`→Train, `HotelStatement`→Hotel, `RideHailing*`→CityTransport
5. **全文回退**：搜索所有上述关键词在全文中的出现
6. **提取字段补充**：用 seller 和 item 的 `ExtractedField` 再次判断

### 3.4 住宿发票特殊处理

当分类为 Hotel 时，额外解析 `hotel_detail`（`invoice_parser.rs:131-153`）：
- 从备注栏解析 `订单日期:M-DD至M-DD` 获取入住/离店日期和天数
- 从备注栏正则 `共N天` 提取天数
- 从商品明细区域 `*住宿服务*...数量` 提取数量
- 交叉验证：备注天数 vs 商品数量，不一致时取较大值

## 4. 行程单解析与配对

### 4.1 行程单解析 (`itinerary_parser.rs`)

支持 4 种格式：
1. **标准格式**：`2025-08-05 09:30  滴滴出行  ¥35.00`
2. **parangi 表格格式**：`1 专车 04-22 21: 成都 ... 60.6 195.37`
3. **天府通格式**：`2026-04-24 17:58:59 ... 3出站：花牌坊 APP`
4. **回退格式**：找 `¥金额` 模式

### 4.2 发票-行程单配对 (`invoice_pipeline.rs:145-179`)

```rust
pair_invoices_with_itineraries(invoices, itinerary_docs, tolerance=0.01)
```

- 对每个行程单文档，遍历已解析的发票列表
- 匹配条件：发票无已关联行程 + 金额差额在 0.01 元以内（严格对应、1分钱都不差）
- 匹配成功：将发票类别设为 `CityTransport`，关联行程明细和文件名
- 匹配失败：为行程单创建一张虚拟发票（seller_name="市内交通"，金额=行程合计）

## 5. 支付账单导入

### 微信账单 (`wechat_parser.rs`)
- 支持 `.xlsx` 格式（`calamine` 库读取 Excel）
- 自动定位 "交易时间" 表头行
- 提取：交易时间、交易类型、商户名称、金额、支付方式、交易单号等
- 处理退款逻辑：
  - 收+退款→金额为负
  - 全额退款→跳过
  - 部分退款→净额=原支付-退款
  - 正常支出→正数
- 提取优惠金额（`已优惠¥0.80`）存入 `discount` 字段

### 支付宝账单 (`alipay_parser.rs`)
- 支持 `.csv` 格式（GBK 编码，用 `encoding_rs` 解码）
- 支持退款关联（通过交易号前缀匹配）
- `total_value() = amount + discount`（商家实际收入）

## 6. 发票-支付匹配

### 6.1 简单批量匹配 (`matching/batch.rs`)

```rust
batch_match(invoices, payments, tolerance)
```

对每张发票（按顺序逐一匹配，已用的支付标记为已占用）：

**普通发票**（非 CityTransport 或无行程）：
- `engine.match_one_to_one`：在可用的支付记录中找金额最接近且在容差范围内（默认 1.00 元）的单笔支付

**CityTransport 带行程的发票**：
- 多行程条目：走 `match_itinerary_to_payments`（两轮匹配算法）
- 单行程条目：走 `match_one_to_many`（子集求和）

**返回**：`BatchMatchResult { matched, unmatched_invoices, unmatched_payments }`

### 6.2 行程逐条匹配算法 (`batch.rs:73-159`)

两轮匹配：
- **第1轮（宽容匹配）**：对每个行程条目，先按服务商（滴滴/高德等）筛选支付商户匹配；匹配不上就放宽到所有商户。记录各商户出现次数
- **确定真实商户**：出现次数最多的商户为真实商户
- **第2轮（精确锁定）**：只从真实商户的支付中重新逐条匹配

**支付金额异常过滤**：`pay.amount / entry.amount` 比例必须在 0.33~3.0 之间

**含高速费匹配**：当支付金额 > 行程金额且差额 <= 行程金额时，判断支付时间和行程时间是否在同一天或次日凌晨

### 6.3 子集求和匹配 (`engine.rs:56-159`)

递归搜索：从候选支付中找子集，使 `|invoice.amount - sum(subset)| <= tolerance`
- 候选上限 20 笔，子集大小上限 10
- 剪枝：超过容差或子集过大时停止

### 6.4 优化批量匹配 (`batch_optimizer.rs`)

使用 `MultiDimensionalScorer` 四维打分：
- **金额 (40%)**：差额=0 得 1.0，<=5 得 0.5~1.0，>5 得 0
- **商户名相似度 (30%)**：精确匹配 1.0、包含关系 0.9、Levenshtein>0.7 返回相似度、品牌关键词匹配 0.85、否则 0
- **时间接近度 (20%)**：同天 1.0、差1天 0.9、3天 0.7、7天 0.5、>7天 0
- **类别匹配 (10%)**：按发票类别匹配支付分类关键词

**置信度阈值**：>=0.7 高置信度直接接受；0.5~0.7 低置信度暂存。若支付未被其他高置信度匹配占用则接受

## 7. 报销单计算 (`form_builder.rs`)

从 `MatchResult` 列表和差旅信息构建 `ReimbursementForm`：

### 7.1 基础参数
- **出差天数**：`travel_end - travel_start + 1`（最少 1 天）
- **伙食补助标准**：**100 元/天**
- **住宿费标准**：根据目的地查询 `hotel_standard.rs`（342 城市数据）

### 7.2 城市间交通费
- 按类别分组：车船票（Train）、飞机票（Flight）、订退改签票（TicketChange）
- 每类单据张数 + 申报金额 = 实际金额合计数

### 7.3 市内交通费
- 实际金额 = 所有 CityTransport 发票金额合计
- **封顶规则**：`可报销金额 = min(实际金额, 80元/天 × 出差天数)`
- 含往返当日，平均每天不超过 80 元

### 7.4 住宿费
- 逐张酒店发票计算：
  - 有 `hotel_detail`：使用 `detail.nights` 作为住宿天数
  - 无 detail：估算为 `travel_days - 1`（最少 1 天）
  - **封顶规则**：`可报销金额 = min(发票金额, 住宿标准价/晚 × 天数)`
- 住宿标准查询（`hotel_standard.rs`）：
  1. 直接匹配 xlsx 规则（如 "深圳市" 命中 450 元行）
  2. 通过 city-province 映射找到省份（342 城市数据）
  3. 用省份匹配规则
  4. 无匹配返回默认 **350 元/晚**

### 7.5 伙食补助
- `金额 = 100元/天 × 出差天数`（固定额度，不需发票）

### 7.6 总计

total_amount = train_amount + flight_amount + ticket_change_amount
             + min(city_transport_actual, 80 × days)
             + hotel_capped_amount
             + 100 × days
             + baggage + meal_receipt - advance_payment

## 8. 输出生成

### 8.1 报销单 HTML（主力输出）
`form_html_generator.rs` → 生成 A4 横向《差旅费报销单》：
- 个人信息行（姓名、部职别、同行人数）
- 差旅信息行（到达地点、出差起止日期、天数）
- 城市间交通费明细（车船票/飞机票/订退改签票 + 小计）
- 市内交通费
- 住宿费分级明细（战区级以上/军级/师级/其他人员）
- 伙食补助
- 行李托运费/凭据报销伙食费/预借款
- **中文大写金额转换**（`amount_to_chinese`，如 `捌仟壹佰叁拾贰元柒角捌分`）

### 8.2 报销单 PDF（`form_generator.rs`）
- 使用 `genpdf` 库生成简单文本 PDF

### 8.3 发票-支付对照单

有三种输出格式：
- **对照表 PDF**（`comparison_generator.rs`）：genpdf 文字版，列出已匹配、未匹配发票、未匹配支付
- **对照表 HTML 含发票图片**（`comparison_html_generator.rs`）：用 pdfium 将发票 PDF 转为 PNG，嵌入 HTML 展示
- **对照表 PDF 含发票原始图像**（`comparison_image_pdf_generator.rs`）：用 `printpdf` 直接嵌入发票图片到 PDF

---

## 9. 去重 (`dedup.rs`)

- **有发票号码** → 按号码去重
- **无发票号码** → 按 `金额_日期_销售方` 组合去重
- 保留首次出现，后续视为重复

    ├── .jpg/.png ──► OCR (PaddleOCR)   │

    ├── .xlsx ──► wechat_parser         │
    └── .csv ──► alipay_parser          ▼
                                  invoice_parser

                                  classify_from_regions/full_text
                                  │
                                  ▼
                            pair_invoices_with_itineraries
                                  │
                                  ▼

                                  ▼
