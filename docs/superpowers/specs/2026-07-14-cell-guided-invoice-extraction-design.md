# 单元格引导发票提取设计

## 背景

pdfplumber fork 已修复中国发票单元格识别（bar-rect 单边 + 按行成格）。`find_tables()` 现在能正确识别发票表格结构并填充单元格文本。但生产代码中 `find_tables()` 完全未使用——发票提取仍依赖纯文本正则 + 坐标回退。

## 目标

用 `find_tables()` 的表格结构引导发票字段提取，作为现有正则/坐标方法的补充层。

## 方案：单元格引导提取 + 正则回退

### 数据流

1. PDF 打开时同时调用 `find_tables()`（零额外开销）
2. `parse_invoice_text`（正则）先跑
3. 缺失字段用单元格提取补充
4. 仍缺失则走现有坐标/parangi/zpdf/OCR 回退

### 表格结构（跨发票类型一致）

| 行标签 | 值单元格内容 |
|--------|------------|
| 销售方信息 | "名称：xxx 公司名 税号..." |
| 购买方信息 | "名称：xxx 税号..." |
| 价税合计（大写） | "¥ 523.57 壹佰..." |
| 备注 | 酒店详情/订单信息等 |
| 项目名称 | "*运输服务*客运服务费..." |

### 字段覆盖

- ✅ 销售方/购买方名称、金额、备注、项目名称、酒店详情、分类
- ❌ 发票号码、日期（不在表格中，仍用正则）

### 回退条件

无表格 / 单元格文本空 / CID 乱码 → 自动回退到现有管道
