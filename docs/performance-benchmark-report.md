数据规模增长 vs 处理时间增长：

## 4. 性能瓶颈分析

### 4.1 主要瓶颈

#### 1. **算法复杂度问题**
- 当前复杂度: O(n_invoice × n_payment)
- 问题: 大规模数据时性能下降明显
- 影响: 1000发票+10000支付耗时15.7秒

#### 2. **一对多匹配性能**
- 子集求和问题（Subset Sum）
- 当前实现: 递归搜索，复杂度高
- 影响: 市内交通场景性能受限

#### 3. **候选筛选效率**
- 当前阈值: 0.5
- 问题: 需要评估大量候选支付记录
- 影响: 增加不必要的计算开销

### 4.2 优化建议

#### 短期优化（Phase 5.4 预备）
1. **索引优化**: 为支付记录建立时间、金额索引
2. **候选筛选优化**: 提高候选阈值，减少候选数量
3. **缓存机制**: 缓存相似度计算结果

#### 中期优化（Phase 6+）
1. **并行处理**: 使用 Rayon 并行化匹配计算
2. **智能策略**: 根据数据特征动态选择匹配策略
3. **算法优化**: 使用动态规划优化一对多匹配
