# 发票报销自动化系统 - 项目规格

## 项目概述

个人出差报销自动化工具，用于收集发票、匹配支付记录、自动生成报销表单。

---

## 目标用户

出差人员，个人使用，简化报销流程。

---

## 核心功能

### 1. 发票收集与识别

**输入来源：**
- 纸质发票照片（手机拍照）
- 电子发票 PDF
- 发票链接/二维码

**提取字段：**
- 发票金额
- 销售方名称
- 项目名称/商品明细
- 开票日期
- 发票号码（用于去重）

**智能分类（基于销售方名称 + 项目名称）：**

| 类别 | 识别关键词 |
|------|------------|
| 高铁/车船票 | 铁路、高铁、火车、客运 |
| 飞机票 | 航空、机票、机场 |
| 住宿费 | 酒店、宾馆、住宿、招待所 |
| 市内交通 | 出租、网约车、滴滴、高德、交通 |
| 餐饮费 | 餐饮、饭店、食品、餐厅 |

---

### 2. 支付账单导入

**支持格式：**
- 微信账单导出（CSV/Excel）
- 支付宝账单导出（CSV/Excel）

**提取字段：**
- 交易时间
- 交易金额
- 交易单号
- 商户名称
- 交易类型

---

### 3. 发票-支付匹配

**匹配规则：**

| 场景 | 发票 | 支付单 | 匹配逻辑 |
|------|------|--------|----------|
| 高铁/飞机 | 1张 | 1笔 | 金额匹配（允许误差） |
| 住宿 | 1张 | 1笔 | 金额匹配 |
| 打车 | 1张发票 + 1张行程单 | 多笔 | 行程单汇总金额匹配发票，再拆分各支付单 |

**误差容忍：**
- 允许小额差异（优惠券、满减等）
- 误差阈值：可配置，默认 ±1.00 元

---

### 4. 行程单处理（打车场景）

**输入：**
- 打车发票 PDF
- 打车行程单 PDF（滴滴/高德等）

**处理流程：**
1. 解析行程单，提取各行程金额
2. 汇总金额匹配发票金额
3. 各行程匹配对应支付订单

---

### 5. 报销表单生成

**输出格式：**
- PDF 表单（主要）
- Excel 表单（可选）

**报销类别（固定模板）：**

```
城市间交通费
├── 车、船票（高铁）
├── 飞机票
└── 订（退、改签）票及交通保险费

市内交通费

住宿费

餐补/伙食补助
```

**表单内容：**
- 基本信息：姓名、部职别、出差日期、同行人数
- 各类别：单据张数、申报金额
- 支付单号（关联显示）
- 总计金额

---

### 6. 发票-支付对照 PDF 生成

生成一个包含所有发票及对应支付记录的完整 PDF，用于报销提交。

**普通发票（高铁/飞机/住宿）：**
```
┌─────────────────────────────────┐
│         发票图片/内容            │
│                                 │
│   金额：¥553.00                 │
│   类型：高铁票                   │
└─────────────────────────────────┘
┌─────────────────────────────────┐
│         支付记录                 │
│   支付单号：4200001234567890     │
│   支付时间：2025-08-04 14:30    │
│   支付金额：¥553.00             │
│   支付方式：微信                 │
└─────────────────────────────────┘
          ── 分页 ──
```

**打车发票（特殊格式）：**
```
┌─────────────────────────────────┐    ← 第1页
│         打车发票图片             │
│   金额：¥256.00                 │
│   发票号码：12345678             │
└─────────────────────────────────┘

┌─────────────────────────────────┐    ← 第2页
│         行程单第1页              │
│   2025-08-05 09:30 滴滴出行     │
│   起点：酒店  终点：客户公司     │
│   金额：¥35.00                  │
└─────────────────────────────────┘

┌─────────────────────────────────┐    ← 第3页
│         行程单第2页              │
│   ...更多行程                    │
└─────────────────────────────────┘

┌─────────────────────────────────┐    ← 最后一页
│     行程-支付对照表              │
├──────────┬──────────┬───────────┤
│  时间    │  金额    │  改付单号  │
├──────────┼──────────┼───────────┤
│ 09:30   │ ¥35.00  │ 4200001234│
│ 14:00   │ ¥42.00  │ 4200005678│
│ 18:30   │ ¥28.00  │ 4200009012│
│ ...     │ ...     │ ...       │
├──────────┼──────────┼───────────┤
│ 合计    │ ¥256.00 │           │
└──────────┴──────────┴───────────┘
          ── 分页 ──
```

**PDF 整体结构：**
1. 封面（可选）：报销人信息、日期范围、总金额
2. 分类排列的发票-支付页：
   - 城市间交通费（高铁、飞机、退改签）
   - 市内交通费（打车等）
   - 住宿费
   - 其他
3. 汇总页：各类别张数、金额、总计

## 技术栈

### 前端（Tauri + Vue 3）
- **框架：** Tauri 2.x
- **UI：** Vue 3 + TypeScript
- **构建工具：** Vite
- **样式：** TailwindCSS
- **状态管理：** Pinia
- **UI组件库：** Element Plus / Naive UI（待定）

### 后端（Rust）
- PDF 解析：`lopdf` / `pdf-extract`
- PDF 生成：`printpdf` / `genpdf`
- Excel 处理：`calamine`（读取）、`rust_xlsxwriter`（写入）
- 图片处理：`image`
- OCR 调用：HTTP client 调用 Python OCR 服务

### OCR 服务（Python）
- **开源模型：** PaddleOCR / RapidOCR
- **部署方式：** 本地服务，Tauri 通过 HTTP 调用
- **服务端口：** localhost:8080

### PDF 生成库
- **Rust：** `printpdf`（底层）、`genpdf`（高级封装）
- **前端预览：** `pdf-lib`（JavaScript）

### 打包分发
- Windows: .msi / .exe
- macOS: .dmg / .app
- Linux: .deb / .AppImage

## 用户工作流

1. **导入发票** → 拖拽/选择文件，自动识别类型
2. **导入账单** → 微信/支付宝导出文件
3. **智能匹配** → 系统自动匹配发票与支付单
4. **人工确认** → 查看匹配结果，手动调整
5. **生成表单** → 一键生成报销 PDF

---

## 非功能性需求

- **响应时间：** OCR 单张发票 < 3秒
- **准确率：** 发票识别 > 95%，匹配准确 > 90%
- **离线可用：** 无需联网即可使用（OCR 本地运行）
- **隐私保护：** 数据不上传云端，本地处理
